Read the Docs Try Examples
backend/server.ts
import { z } from 'zod'; import { initTypeOwl } from 'typeowl/server'; const typeowl = await initTypeOwl(); // GET /api/users → returns User[] typeowl.endpoint(app, 'GET', '/api/users', { response: 'User[]', }, async () => users); // POST /api/users → validates body with Zod const CreateUserSchema = z.object({ email: z.string().email(), name: z.string(), }); typeowl.endpoint(app, 'POST', '/api/users', { body: CreateUserSchema, response: 'User', }, async ({ body }) => createUser(body));
frontend/api.ts
// Types synced automatically! ✨ import type { User } from 'typeowl/types'; // Full autocomplete, type-safe responses const users: User[] = await fetch('/api/users') .then(r => r.json()); // POST with typed body const newUser: User = await fetch('/api/users', { method: 'POST', body: JSON.stringify({ email: 'alice@example.com', name: 'Alice' }) }).then(r => r.json());

Why TypeOwl?

True decoupling between frontend and backend — unlike tRPC or ts-rest

No Monorepo Required

Backend and frontend in separate repos? Different teams? No shared packages needed. TypeOwl bridges them over HTTP.

Independent Deploys

Commit types with your code. Frontend and backend deploy separately without breaking each other.

Pure Frontend Friendly

Point to production URL and sync. Frontend devs get real types without needing backend code access.

On-Demand Sync

You control when types update: during dev, in CI/CD, or manually. No forced updates from backend changes.

Incremental & Fast

Hash-based comparison means only changed files download. Instant syncs when nothing changed.

Optional Zod Validation

Use typeowl.endpoint() for runtime validation, or extract types directly from .ts files.

How It Works

Simple architecture, powerful results

Backend (deployed)
/api/users ← Your actual API
/__typeowl ← Lightweight manifest (JSON)
/__typeowl/types/*.d.ts ← TypeScript definitions
HTTP (dev, CI/CD, or on-demand)
↓
Frontend (any environment)
1. typeowl sync ← Fetches manifest, compares hashes
2. Downloads changed type files only (incremental!)
3. Commit types → independent deploys!
4. import type { User } from 'typeowl/types' ← Full autocomplete!

How Does It Compare?

Different tools for different architectural needs

TypeOwl

Decoupled
  • Separate repositories
  • No shared code needed
  • Independent deploys
  • Existing REST APIs
  • On-demand sync
  • Optional validation

Ideal for separate teams & repos

tRPC

Integrated
  • End-to-end type safety
  • Built-in validation
  • Excellent DX
  • Requires monorepo
  • Coupled deploys
  • Custom protocol

Ideal for full-stack monorepos

ts-rest

Contract
  • REST compatible
  • Type-safe contracts
  • Built-in validation
  • Shared npm package
  • Coupled releases
  • Contract syncing

Ideal for shared contract workflows

All three provide excellent type safety. TypeOwl shines in flexibility and when teams and repos are separate.
